# Infra Monitoring Project

Проект по настройке мониторинга, контейнеризации и CI/CD для простого API-сервиса.

## Структура проекта

- check_api.sh — скрипт проверки доступности API.
- analyze_logs.sh — скрипт генерации и анализа логов access.log.
- docker-compose.yml — конфигурация стека (api + nginx).
- nginx.conf — конфигурация прокси-сервера.
- .github/workflows/ci.yml — пайплайн CI/CD.

## Запуск

### Bash-скрипты

Для проверки API:
chmod +x check_api.sh
./check_api.sh https://httpbin.org/status/200

Для анализа логов:
chmod +x analyze_logs.sh
./analyze_logs.sh

### Docker Compose

Запуск стека в фоновом режиме:
sudo docker compose up -d

Проверка работы:
curl http://localhost:80

Остановка:
sudo docker compose down

## Процесс безопасного деплоя на удаленный сервер (SSH и SCP)

Развертывание проекта на удаленном сервере (VPS) осуществляется с использованием протокола SSH. Этот подход позволяет безопасно передавать файлы и управлять сервером без использования незащищенных паролей.

### 1. Генерация SSH-ключей

Для аутентификации по ключам (вместо ввода пароля) необходимо сгенерировать пару ключей: приватный и публичный. Приватный ключ остается на локальной машине и никогда не передается, а публичный ключ устанавливается на сервере.
Рекомендуется использовать современный и безопасный алгоритм Ed25519:

ssh-keygen -t ed25519 -C "your_email@example.com"

В процессе выполнения команды система попросит указать путь для сохранения ключей (по умолчанию ~/.ssh/id_ed25519) и кодовую фразу (passphrase) для дополнительной защиты. Если passphrase не нужна, можно просто нажать Enter.

### 2. Копирование публичного ключа на сервер

Чтобы сервер разрешал подключение без ввода пароля, наш публичный ключ (~/.ssh/id_ed25519.pub) должен быть добавлен в файл authorized_keys на удаленном сервере. Утилита ssh-copy-id автоматизирует этот процесс, создавая нужные директории и выставляя правильные права доступа:

ssh-copy-id user@your_server_ip

(Где user — это имя пользователя на сервере, а your_server_ip — IP-адрес или доменное имя сервера).

После этого можно проверить подключение командой ssh user@your_server_ip. Если все настроено верно, сервер пустит вас без запроса пароля.

### 3. Передача файлов проекта на сервер

Для передачи исходного кода на сервер можно использовать утилиту scp (Secure Copy Protocol). Предварительно проект нужно упаковать в архив, чтобы не передавать файлы по одному. Архивация также позволяет исключить из передачи лишние файлы (например, кэш, логи или папку .git).

Способ 1: Передача готового архива через SCP
Сначала создаем архив (tar.gz) в текущей директории:
tar -czf project.tar.gz .

Затем передаем его на сервер в нужную директорию (например, /var/www/myproject):
scp project.tar.gz user@your_server_ip:/var/www/myproject/

Способ 2: Потоковая передача через tar и ssh
Этот способ удобен тем, что не создает промежуточный архив на локальной машине. Мы упаковываем файлы и сразу передаем поток данных по SSH, где на сервере он распаковывается «на лету»:
tar -czf - . | ssh user@your_server_ip "tar -xzf - -C /var/www/myproject/"

(Флаг -C указывает директорию на сервере, куда нужно распаковать файлы).

### 4. Запуск и обновление проекта на сервере

После того как файлы успешно переданы, необходимо подключиться к серверу по SSH, перейти в директорию с проектом и запустить контейнеры:

ssh user@your_server_ip
cd /var/www/myproject/
sudo docker compose up -d

Если в будущем потребуется обновить код проекта (деплой новой версии), процесс повторяется: передаем новые файлы любым из способов выше (перезаписывая старые) и перезапускаем стек командой sudo docker compose up -d --build. Docker автоматически подхватит изменения.
